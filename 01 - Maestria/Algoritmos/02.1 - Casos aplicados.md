## Ejercicio 1 — Función de limpieza

```python
def convertir_a_float(texto: str) -> float | None:
    return float(texto) if texto != "" else None

def texto_o_none(texto: str) -> str | None:
    return texto if texto != "" else None

def limpiar(fila: dict) -> dict:
    return {
        "especie": texto_o_none(fila["species"]),
        "isla": texto_o_none(fila["island"]),
        "pico_mm": convertir_a_float(fila["bill_length_mm"]),
        "alto_pico_mm": convertir_a_float(fila["bill_depth_mm"]),
        "aleta_mm": convertir_a_float(fila["flipper_length_mm"]),
        "masa_g": convertir_a_float(fila["body_mass_g"]),
        "sexo": texto_o_none(fila["sex"]),
    }

pinguinos = [limpiar(f) for f in crudo]
```

```
{'especie': 'Adelie', 'isla': 'Torgersen', 'pico_mm': 39.1, ..., 'sexo': 'MALE'}
{'especie': 'Adelie', 'isla': 'Torgersen', 'pico_mm': None, ..., 'sexo': None}   # fila con faltantes
```

> [!tip] Dos decisiones de diseño que valen la pena señalar
> **Una función auxiliar por tipo de dato**, no la lógica de conversión repetida siete veces — exactamente el criterio de [[funciones, parametros y alcance]]: "empaquetar un procedimiento bajo un nombre para invocarlo cuantas veces haga falta, corregirlo en un solo lugar". Si mañana cambia el criterio de "vacío" (por ejemplo, tratar también `"NA"` como faltante), se corrige en **un** lugar, no en siete.
>
> **Anotaciones de tipo** (`texto: str`, `-> float | None`): no cambian el comportamiento en tiempo de ejecución (Python sigue siendo dinámicamente tipado), pero documentan el contrato de la función para quien la lee después — incluida la propia persona que la escribió, una semana más tarde. `float | None` es la forma moderna (Python ≥ 3.10) de escribir "esto puede ser un `float` o puede ser `None`", la misma idea que ya aparece sin anotar en [[datos faltantes y None]].

## Ejercicio 2 — Reporte de calidad de datos, generalizado

```python
def contar_faltantes(registros: list[dict]) -> dict[str, int]:
    conteo = {campo: 0 for campo in registros[0]}
    for registro in registros:
        for campo, valor in registro.items():
            if valor is None:
                conteo[campo] += 1
    return conteo
```

```
Especie: 0 (0.00%)
Isla: 0 (0.00%)
Pico_mm: 2 (0.58%)   Posiciones: [3, 339]
Alto_pico_mm: 2 (0.58%)   Posiciones: [3, 339]
Aleta_mm: 2 (0.58%)   Posiciones: [3, 339]
Masa_g: 2 (0.58%)   Posiciones: [3, 339]
Sexo: 11 (3.20%)   Posiciones: [3, 8, 9, 10, 11, 47, 246, 286, 324, 336, 339]
```

> [!important] `conteo = {campo: 0 for campo in registros[0]}` no es un detalle menor
> Tomar los nombres de campo del **primer registro**, en vez de escribirlos a mano (`{"especie": 0, "isla": 0, ...}`), es lo que hace que `contar_faltantes` sirva para **cualquier** dataset con esa forma, no solo para pingüinos — la diferencia entre una función genérica y un script de un solo uso. Es una comprensión de diccionario (ver [[comprensiones de listas]], que desarrolla la misma idea para listas — el patrón `{clave: valor for ... in ...}` es exactamente análogo).

**Interpretación real del ejercicio**: las filas 3 y 339 tienen **todos** los campos numéricos vacíos (y tampoco tienen sexo) — son registros completamente vacíos, candidatos claros a descartar. Los otros 9 casos sin sexo sí tienen el resto de las mediciones completas: eliminar esas filas enteras perdería datos útiles: mejor conservarlas y excluirlas solo de los análisis que usen `sexo`.

## Ejercicio 3 — Clasificar con condicionales

```python
def categoria_masa(masa: float | None) -> str:
    if masa is None:
        return "sin dato"
    elif masa >= 4500:
        return "pesado"
    elif masa >= 3500:
        return "medio"
    else:
        return "liviano"
```

```
medio: 153
liviano: 71
sin dato: 2
pesado: 118
```

> [!warning] El orden de las condiciones, aplicado
> `masa is None` va **primero**, antes de cualquier comparación numérica — exactamente la advertencia de [[condicionales y evaluacion de verdad]]: `None >= 4500` no se evalúa como "falso", directamente **rompe** con `TypeError`, porque Python no sabe comparar `None` con un número. Es la misma clase de error, en sentido inverso, que evaluar `elif masa > 4000` antes que `elif masa > 5000` en la clase — acá el bug no sería "un caso mal clasificado" sino que el programa **no correría en absoluto** para ningún pingüino sin dato de masa.

## Ejercicio 4 — Agrupación reutilizable con desvío

```python
def resumen_por(registros: list[dict], clave_grupo: str, clave_valor: str) -> dict:
    valores_por_grupo = {}
    for r in registros:
        valor = r[clave_valor]
        if valor is None:
            continue
        grupo = r[clave_grupo]
        valores_por_grupo.setdefault(grupo, []).append(valor)

    resumen = {}
    for grupo, valores in valores_por_grupo.items():
        n = len(valores)
        promedio = sum(valores) / n
        suma_cuadrados = sum((v - promedio) ** 2 for v in valores)
        desvio = math.sqrt(suma_cuadrados / (n - 1))
        resumen[grupo] = (promedio, desvio, min(valores), max(valores), n)
    return resumen
```

```
Masa por especie
Adelie      3700.7 ± 458.6 g   (2850.0–4775.0, n=151)
Chinstrap   3733.1 ± 384.3 g   (2700.0–4800.0, n=68)
Gentoo      5076.0 ± 504.1 g   (3950.0–6300.0, n=123)

Largo de aleta por especie
Adelie      190.0 ± 6.5 mm   (172.0–210.0, n=151)
Chinstrap   195.8 ± 7.1 mm   (178.0–212.0, n=68)
Gentoo      217.2 ± 6.5 mm   (203.0–231.0, n=123)
```

> [!tip] `setdefault(grupo, []).append(valor)` — el mismo group-by-a-mano, versión "lista" en vez de "acumulador numérico"
> Es la variante de [[bucles for, while y el patron acumulador]] donde en vez de acumular una suma con `dict.get(clave, 0) + valor` (como en el Ejercicio 5 de [[01.1 - Casos aplicados|la actividad de clase 1]]), se acumula una **lista completa** por grupo — necesario acá porque después hace falta el mínimo, el máximo y el desvío, no solo el total. `setdefault` hace en una línea lo que sería `if grupo not in valores_por_grupo: valores_por_grupo[grupo] = []` seguido de `.append(...)`.

**Interpretación real del ejercicio**: por masa, solo Gentoo se distingue con claridad (su promedio queda a ~3 desvíos de las otras dos especies); Adelie y Chinstrap son prácticamente indistinguibles por masa sola (32 g de diferencia entre promedios, contra desvíos de ~400 g). El largo de aleta separa mejor: Gentoo queda a más de 3 desvíos de las otras dos, y Adelie/Chinstrap mejoran a ~1 desvío de diferencia — todavía no alcanza para separarlas del todo, haría falta cruzar con `pico_mm` o `alto_pico_mm`. Agrupar por sexo en cambio da desvíos mucho mayores que por especie, porque cada grupo de sexo mezcla las tres especies (incluida la Gentoo, mucho más pesada) — agrupar por la variable "equivocada" infla la variabilidad y esconde la estructura real.

## Ejercicio 5 — Búsqueda con bucles: lineal a mano

```python
def buscar_primero(registros: list[dict], clave: str, valor) -> dict | None:
    pasos = 0
    for registro in registros:
        pasos += 1
        if registro[clave] == valor:
            return registro
    return None
```

```
Alto_pico = 16.9:  se necesitaron 45 pasos
Alto_pico = 30:    se necesitaron 344 pasos (no encontrado)
Masa = 6300:       se necesitaron 238 pasos
```

> [!important] Esto es una búsqueda lineal midiendo su propio costo
> Contar `pasos` explícitamente convierte la función en una demostración en vivo de [[complejidad O(1) vs O(n)]]: encontrar algo que está temprano en la lista (45 pasos) es barato; **no** encontrar algo exige recorrer la lista **entera** (344 pasos, el peor caso siempre) — el mismo peor caso que un `elemento in lista` común. `buscar_extremo` (el máximo, escrito a mano sin `max()`) hace exactamente lo mismo que hace `max()` por dentro: un recorrido único llevando registro del mejor valor visto hasta el momento — es, en esencia, el mismo patrón acumulador de siempre, con "quedarme con el mayor" en vez de "sumar".

## Ejercicio 6.a — Suma recursiva

```python
def suma_recursiva(lista: list[float]) -> float:
    if len(lista) == 0:
        return 0
    return lista[0] + suma_recursiva(lista[1:])
```

```
[1, 2, 3] -> 6 (esperado 6) OK
[] -> 0 (esperado 0) OK
[9.5, 10, 9] -> 28.5 (esperado 28.5) OK
```

Caso base (`lista == []` → 0) y caso recursivo ("el primero, más la suma del resto") calcados de la estructura que ya desarrolla [[recursion y memoizacion]] con el ejemplo de `invertir(lista)` — "cualquier estructura que se pueda partir en primero + resto es candidata natural a recorrerse recursivamente".

## Ejercicio 6.b — El costo de recalcular: coeficiente binomial

$C(n,k)$ cuenta de cuántas formas se pueden elegir $k$ elementos entre $n$ — la misma cantidad que devuelve el triángulo de Pascal, con la definición recursiva:

$$C(n,k) = C(n-1,k-1) + C(n-1,k) \qquad C(n,0)=1, \quad C(n,n)=1$$

```python
llamadas = 0
def combinaciones(n: int, k: int) -> int:
    global llamadas
    llamadas += 1
    if k == 0 or n == k:
        return 1
    return combinaciones(n-1, k-1) + combinaciones(n-1, k)
```

```
 n    k       C        llamadas
------------------------------
10    5      252          503
15    7     6435        12869
20   10   184756       369511
24   12  2704156      5408311
```

Con memoización (un diccionario `{(n,k): resultado}`, mismo patrón que `fibonacci_memo`):

```
 n    k       C        llamadas
------------------------------
10    5      252           51
15    7     6435          113
20   10   184756          201
24   12  2704156          289
```

`C(24,12)` pasa de 5.408.311 llamadas a 289 — una mejora de casi 14.000 veces, verificada además en tiempo real de ejecución (1617 ms sin memoizar contra 0,12 ms memoizado).

> [!definition] Qué es $\binom{n}{k}$, formalmente
> El coeficiente binomial, "n elige k", es la cantidad de subconjuntos de tamaño $k$ que se pueden formar a partir de un conjunto de $n$ elementos, sin importar el orden: *"The number of selections of k items from a set of n without duplicates is given by the binomial coefficient [...] pronounced 'n choose k'"*, con la fórmula cerrada equivalente $\binom{n}{k} = \frac{n!}{k!(n-k)!}$. *Fuente: [[Essential Algorithms A Practical Approach to Computer Algorithms]], cap. 9 (Recursion).* La recursión de Pascal que usa esta actividad no aparece en ese libro (que solo da la fórmula cerrada) — es la forma equivalente, más lenta de calcular pero más directa de programar sin necesitar factoriales.

> [!important] Es el mismo fenómeno que Fibonacci, con la misma solución — y la bibliografía lo confirma
> `combinaciones(n,k)` se ramifica en **dos** llamadas por cada caso no-base, exactamente como `fibonacci(n)` — un árbol de llamadas que se duplica en cada nivel, de ahí el crecimiento $O(2^n)$ que ya explica [[recursion y memoizacion]] para Fibonacci. Y comparte la causa exacta de la ineficiencia: **subproblemas superpuestos** — $C(n-1,k-1)$ y $C(n-1,k)$ comparan, un nivel más abajo, muchos de los mismos $C(n-2, \cdot)$ entre sí. Memoizar funciona por la misma razón en los dos casos: guardar cada $(n,k)$ ya resuelto evita recorrer dos veces la misma rama del árbol.
>
> No es casualidad que se sienta como "el mismo problema que Fibonacci, con otro nombre": Sedgewick pone, uno junto al otro, un ejercicio sobre Fibonacci recursivo y uno sobre una recursión binaria equivalente al binomial (la distribución de probabilidad binomial, `binomial(N, k, p)`, con la misma forma de árbol: dos llamadas recursivas por nodo), pidiendo en **ambos** con la misma frase textual *"develop a better implementation [...] that saves computed values in an array"* — es decir, memoizar. *Fuente: [[Algorithms-4th-Edition-By-Robert Sedgewick and Kevin Wayne]], ejercicios 1.1.19 y 1.1.27.*
