# Parte A — Árboles

## Ejercicio A1 — Recorridos básicos

Sobre el árbol de taxonomía de minería de datos ya dado en clase:

```python
def listar_hojas(nodo: dict) -> list[str]:
    if not nodo["hijos"]:                 # CASO BASE: sin hijos, soy una hoja
        return [nodo["nombre"]]
    hojas = []
    for rama in nodo["hijos"]:
        hojas += listar_hojas(rama)
    return hojas

def profundidad_de(nodo: dict, nombre: str, nivel: int = 0) -> int | None:
    if nodo["nombre"] == nombre:
        return nivel
    for rama in nodo["hijos"]:
        prof = profundidad_de(rama, nombre, nivel + 1)
        if prof is not None:
            return prof
    return None

def camino_a(nodo: dict, nombre: str) -> list[str] | None:
    if nodo["nombre"] == nombre:
        return [nodo["nombre"]]
    for rama in nodo["hijos"]:
        camino = camino_a(rama, nombre)
        if camino is not None:
            return [nodo["nombre"]] + camino
    return None
```

```
Hojas del árbol: Árbol de decisión, KNN, Regresión logística, SVM, Regresión lineal,
                 Regresión polinómica, K-means, Jerárquico, DBSCAN, PCA, t-SNE

Profundidad de K-means: 3
Camino a K-means: ['Minería de datos', 'Aprendizaje no supervisado', 'Agrupamiento', 'K-means']
```

> [!important] Tres funciones, tres formas distintas de "combinar" lo que devuelven los hijos
> Las tres son recursivas sobre la misma estructura, pero cada una combina las respuestas de los hijos de manera distinta — el mismo espectro que ya traza [[árboles]]:
> - `listar_hojas` **acumula**: concatena (`+=`) lo que devuelve cada hijo, como `contar_nodos` de la clase.
> - `profundidad_de` y `camino_a` **cortan apenas encuentran**: recorren los hijos en un `for`, pero devuelven en cuanto uno de ellos da una respuesta no-`None` — no siguen probando los hijos restantes una vez que hay resultado. Es el mismo patrón de `buscar` de la clase (ver [[árboles]]), aplicado a un árbol general en vez de a un árbol binario de búsqueda: acá no hay regla de orden que permita descartar la mitad del árbol de entrada (no es un BST), así que en el peor caso (nodo inexistente, o en la última rama) sí hay que recorrerlo entero — $O(N)$, no $O(\log N)$.
> - `camino_a` además **reconstruye hacia arriba**: cada nivel que encuentra el camino en un hijo le antepone su propio nombre (`[nodo["nombre"]] + camino`) antes de devolverlo — la respuesta se arma de abajo hacia arriba, a medida que la recursión "sube".

## Ejercicio A2 — Árbol de decisión propio, con cortes mixtos

```python
arbol_de_decision = {
    "campo": "especie",
    "ramas": {
        "Gentoo": {"campo": "masa_g", "umbral": 5000,
                   "si": {"respuesta": "MALE"},
                   "no": {"campo": "pico_mm", "umbral": 47.5,
                          "si": {"respuesta": "MALE"}, "no": {"respuesta": "FEMALE"}}},
        "Adelie": {"campo": "masa_g", "umbral": 3600,
                   "si": {"respuesta": "MALE"},
                   "no": {"campo": "pico_mm", "umbral": 39,
                          "si": {"respuesta": "MALE"}, "no": {"respuesta": "FEMALE"}}},
        "Chinstrap": {"campo": "masa_g", "umbral": 3700,
                      "si": {"respuesta": "MALE"},
                      "no": {"campo": "pico_mm", "umbral": 49,
                             "si": {"respuesta": "MALE"}, "no": {"respuesta": "FEMALE"}}},
    }
}

def predecir_sexo(arbol: dict, pinguino: dict) -> str:
    if "respuesta" in arbol:                                    # CASO BASE: hoja
        return arbol["respuesta"]
    if "ramas" in arbol:                                        # corte categórico
        return predecir_sexo(arbol["ramas"].get(pinguino[arbol["campo"]]), pinguino)
    rama = "si" if pinguino[arbol["campo"]] > arbol["umbral"] else "no"   # corte numérico
    return predecir_sexo(arbol[rama], pinguino)
```

```
Aciertos 280 de 333 -> Exactitud del árbol propio: 84.08 %
Aciertos 168 de 333 -> Exactitud del clasificador trivial (predecir siempre MALE): 50.45 %
```

Verificado de forma independiente en este entorno (recalculando desde el dataset real de pingüinos): coincide exactamente.

> [!important] Dos tipos de nodo interno en el mismo árbol — una idea que la clase no necesitó, pero que es la forma real de un árbol de decisión
> El árbol de la clase (especie a partir de `aleta_mm`/`pico_mm`) usaba **un solo tipo** de corte: siempre numérico (`> umbral`). Este árbol necesita, además, un corte **categórico** — primero preguntar la especie (que no tiene un "mayor" o "menor", tiene ramas con nombre: `"ramas": {"Gentoo": ..., "Adelie": ..., "Chinstrap": ...}`) y recién dentro de cada rama aplicar un corte numérico de masa **distinto para cada especie**. `predecir_sexo` distingue los dos casos mirando qué clave tiene el nodo (`"ramas"` vs. `"umbral"`) antes de decidir cómo bajar un nivel — el mismo patrón de "mirar qué tipo de nodo es antes de procesarlo" que ya usa `predecir` en [[árboles]] para distinguir una hoja de un nodo interno, extendido a un tercer caso.
>
> Esto no es un capricho del ejercicio: los árboles de decisión reales (CART, el algoritmo detrás de `sklearn.tree.DecisionTreeClassifier`) manejan exactamente esta distinción — una variable categórica se parte por pertenencia a un subconjunto de categorías, una variable numérica se parte por un umbral — y **sí o sí** hace falta un umbral distinto por rama cuando, como acá, los grupos tienen escalas distintas: la hembra Gentoo promedio (4679.74 g) pesa más que el macho Adelie promedio (4043.49 g), así que ningún umbral único de masa podría separar bien a la vez dentro de Gentoo y dentro de Adelie.

def maximo_minimo(registros: list[dict]) -> dict:
    maximos, minimos = {}, {}
    for r in registros:
        e = r["especie"]
        if e not in maximos:
            maximos[e] = minimos[e] = r["masa_g"]
        maximos[e] = max(maximos[e], r["masa_g"])
        minimos[e] = min(minimos[e], r["masa_g"])
    return {e: (minimos[e], maximos[e]) for e in maximos}

grafo_por_masa = {}
for e1 in rangos_por_especie:

## Ejercicio B2 — DFS, componentes y camino más corto

```python
def dfs(grafo: dict, origen: str, visitados: set | None = None) -> set:
    if visitados is None:                 # NO usar visitados=set() directo — ver por qué en [[recursion y memoizacion]]
        visitados = set()
    if origen in visitados:
        return visitados
    visitados.add(origen)
    for conexion in grafo[origen]:
        dfs(grafo, conexion, visitados)
    return visitados

def componentes(grafo: dict) -> list[set]:
    grupos, visitados = [], set()
    for nodo in grafo:
        if nodo not in visitados:
            grupo = dfs(grafo, nodo)
            visitados |= grupo
            grupos.append(grupo)
    return grupos
```

```
Alcanzables desde Ana: {Bruno, Diego, Elena, Carla, Ana, Fabián}

Componentes:
  Grupo 1: {Bruno, Diego, Elena, Carla, Ana, Fabián}
  Grupo 2: {Gabriela, Hugo}
```

> [!tip] `componentes` es `dfs` reutilizada, no un algoritmo nuevo
> La función recorre **todos** los nodos del grafo, y por cada uno que todavía no esté en `visitados` (es decir, que no haya sido alcanzado por un DFS anterior) lanza un DFS nuevo desde ahí — cada DFS explora exactamente una componente conexa completa. Es la aplicación directa de lo que ya señala [[grafos y recorridos (DFS, BFS)|la nota de grafos]]: el conjunto que devuelve `dfs` desde un origen **es**, por definición, la lista de nodos alcanzables — y "componente conexa" es, literalmente, "todo lo alcanzable desde un nodo cualquiera de ese grupo". `Gabriela`/`Hugo` quedan aislados del resto exactamente como quedaba `Ushuaia` en el grafo de rutas de la clase: sin ninguna arista que los conecte con el resto, ningún DFS que arranque del otro lado los va a visitar nunca.

```python
def camino_mas_corto(grafo: dict, origen: str, destino: str) -> list[str] | None:
    if origen == destino:
        return [origen]
    visitados = {origen}
    cola = deque([[origen]])
    while cola:
        camino = cola.popleft()
        ultimo = camino[-1]
        for vecino in grafo[ultimo]:
            if vecino in visitados:
                continue
            nuevo = camino + [vecino]
            if vecino == destino:
                return nuevo
            cola.append(nuevo)
            visitados.add(vecino)
    return None
```

```
Camino más corto Ana -> Fabián: ['Ana', 'Bruno', 'Diego', 'Fabián']   (3 saltos)
Camino más corto Ana -> Hugo:   None   (sin conexión)
```

**Respuestas del ejercicio**: hay **2** grupos de investigación aislados entre sí; la distancia de colaboración Ana–Fabián es de **3 saltos**; no existe ningún camino entre Ana y Hugo, porque Hugo solo se conecta con Gabriela, y ese par está completamente desconectado del resto — es la misma idea de "número de Erdős" o "seis grados de separación" que ya conecta [[grafos y recorridos (DFS, BFS)]] con el ejemplo canónico de Sedgewick sobre rutas aéreas.

# Parte C — Complejidad

## Ejercicio C1 — Analizar sin ejecutar

| Función | Complejidad | Por qué |
|---|---|---|
| `f1` | $O(1)$ | Acceder a `lista[len(lista)//2]` es indexado directo, sin recorrer nada. |
| `f2` | $O(n)$ | Un `for` recorre los $n$ elementos una vez, con trabajo constante en cada vuelta. |
| `f3` | $O(n^2)$ | El `for` recorre $n$ elementos, y `x in lista` **dentro** del `for` es, cada vez, otro recorrido de hasta $n$ elementos — bucles anidados, $n \times n$. |
| `f4` | $O(n)$ | Construir `set(lista)` es $O(n)$; después, cada `x in conjunto` es $O(1)$ por hashing — un recorrido de $n$ pasos, cada paso a costo constante. Dos pasadas **secuenciales** (no anidadas) siguen siendo $O(n)$. |
| `f5` | $O(\log n)$ | `n` se divide a la mitad en cada vuelta del `while` — la misma pregunta que responde [[04 - Funciones exponenciales y logaritmicas|un logaritmo]]: "¿cuántas veces puedo dividir $n$ a la mitad antes de llegar a 1?". |
| `f6` | $O(n^3)$ | Tres `for` anidados, cada uno recorriendo hasta $n$ elementos: $n \times n \times n$. |

> [!important] `f3` contra `f4` es el ejercicio entero de [[complejidad O(1) vs O(n)]], en dos funciones casi idénticas
> La única diferencia entre las dos es la estructura de datos usada para preguntar "¿está esto adentro?" — `lista` en `f3`, `conjunto` en `f4` — y esa única diferencia cambia la complejidad total de $O(n^2)$ a $O(n)$. Con $n=10.000$, `f3` hace hasta 100 millones de comparaciones; `f4`, unas 20 mil. Es exactamente el argumento de la clase: "elegir la estructura de datos es una decisión algorítmica", no un detalle de estilo.

## Ejercicio C2 — Determinar la complejidad midiendo

```python
def misterio(n):
    total = 0
    for i in range(n):
        j = 1
        while j < n:
            total += i * j
            j = j * 2
    return total

def medir(f, n, repeticiones=3):
    tiempos = sorted(medir_una_vez(f, n) for _ in range(repeticiones))
    return tiempos[repeticiones // 2]   # mediana
```

Medido de forma independiente en este entorno (mismo método: mediana de repeticiones, tamaños duplicando cada vez):

| $n$ | tiempo (ms) | razón vs. anterior |
|---|---|---|
| 500 | 0,120 | — |
| 1.000 | 0,265 | 2,20× |
| 2.000 | 0,626 | 2,36× |
| 4.000 | 1,438 | 2,30× |
| 8.000 | 3,054 | 2,12× |
| 16.000 | 6,547 | 2,14× |

![[Tiempo de ejecucion de misterio.png]]

**Conclusión (coincide con la de la actividad original, con números propios)**: la razón se mantiene estable alrededor de **2,1–2,4** al duplicar $n$ — ni cerca de 2 (que sería $O(n)$) ni cerca de 4 (que sería $O(n^2)$), consistente con $O(n \log n)$. La lectura del código lo confirma: el bucle exterior (`for i in range(n)`) da $n$ vueltas; el interior (`while j < n: j = j * 2`) **duplica** `j` en cada paso en vez de sumarle 1, así que necesita solo $\log_2 n$ vueltas para superar a $n$ — el mismo argumento de $O(\log n)$ de `f5` de arriba, anidado dentro de un bucle que da $n$ vueltas: $n \times \log_2 n$.

> [!tip] Ampliación — la fórmula exacta, no solo "parece $n\log n$"
> El método de la actividad ("duplicá $n$ y mirá qué le pasa al tiempo") es la versión informal del **doubling ratio** de Sedgewick: $b = \log_2(\text{razón})$ da el exponente exacto en vez de una intuición — desarrollado en detalle, con ejemplos verificados, en [[notación Big O y familias de complejidad]]. Aplicado acá: $\log_2(2{,}2) \approx 1{,}14$, $\log_2(2{,}3)\approx 1{,}20$ — un exponente cercano a 1, **no** a 2, que es exactamente la firma de $O(n\log n)$ (crece "casi lineal", con el $\log n$ como corrección chica) contrastada con la firma de $O(n^2)$ (exponente cercano a 2) que ya se midió sobre `hay_duplicados_lento` en la clase.
